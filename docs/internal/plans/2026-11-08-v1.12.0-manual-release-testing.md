## F. Playlist voting — remote and `!playlistvote`

Needs **≥2 real listeners** in the bot channel (requester + peer). For 100% threshold with 3 humans, use **≥3**.

**Admin settings:** Media / playlist vote settings for the virtual server (enable voting, threshold %, max tracks).  
**Remote:** open vote → ballot **yes/no**.  
**Chat:** `!playlistvote yes` / `!playlistvote no` (private replies).

| # | Steps | Expected | Severity | Listeners |
|---|--------|----------|----------|-----------|
| F1 | Voting on; sole listener proposes | Auto-queues (sole electorate) | Blocker | 1 |
| F2 | Two listeners; requester opens; peer remote **yes** | Passes once; queues once; history once | Blocker | ≥2 |
| F3 | Same setup; peer chat `!playlistvote yes` | Same as F2 | Blocker | ≥2 |
| F4 | Requester chat `!playlistvote no` | Cancels; nothing queued / no history | Blocker | ≥2 |
| F5 | Peer chat after remote already passed | No second queue; private “no open vote” / ended | Blocker | ≥2 |
| F6 | Concurrent remote + chat yes near threshold | Exactly one queue; one history set | Blocker | ≥3 |
| F7 | Private replies / remote JSON | No UIDs, no `/path/to/file` leaks | Blocker | ≥2 |
