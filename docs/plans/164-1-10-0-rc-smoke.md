# #164 / 1.10.0 — Release-candidate smoke checklist

**Status:** Manual checklist, to run in the homelab before the Release Please PR merges. No run results are recorded here yet.  
**Source:** [Issue #271](https://github.com/uniskela/ts6-manager/issues/271), last updated **2026-10-03 04:10:22 UTC**, checked against `main` at `5bd0df0`. Includes the merged PRs since `v1.9.3`; the issue's old Media Bots paths are translated to the current UI, and later merged work is added below.  
**Scope:** Behavior that needs a real TeamSpeak 6 client, an AMD GPU, or a live source. Every phase 2 task (10–17) has merged and is included, along with banner hosting (#287), the console polish (#290), console shortcuts (#294) and inherited stream defaults (#295).

Run the sections in order. Tick a box only after checking it; record **Pass**, **Fail** (with an issue link), or **N/A** (with a reason) in the sign-off. Re-check the scope whenever another 1.10.0 PR merges. Record the tested commit or image tag, host CPU/GPU, TeamSpeak server/client versions, and date with each run.

Do not paste stream URLs, IPTV credentials, tokens, internal hostnames, or screenshots containing them into issues. Refer to test sources as "provider A live channel" or similar.

## 0. Setup

- [ ] Back up the database before testing an upgrade; follow [Upgrading](../upgrading.md). Keep a separate copy for rollback. Verify the shipped SQLite changes preserve existing data: the new `IptvChannelPick` table, the `MusicBot` avatar columns and the `IptvChannel` `tvgCountry`/`tvgLanguage` columns. Hosted banners in `data/channel-banners/` survive the upgrade.
- [ ] On the **homelab test machine**, check out current `main`. For a fresh test stack, copy `.env.pr-test.example` to `.env` only if `.env` does not already exist, then use `docker compose -f docker-compose.pr-test.yml up --build`. Open `http://localhost:3000/setup` and create the admin. Keep environment files private. The Compose file publishes frontend and TeamSpeak ports on all host interfaces by default; use an isolated test machine or a local override matching its access policy.
- [ ] On a private development host, use a local Compose override that replaces published port lists with loopback bindings (for example `127.0.0.1:3000:80`) and removes unneeded Query/metrics ports. Check the effective port lists before starting, and use the existing private access path.
- [ ] Also run the real media checks on the homelab stack with the **AMD GPU (H.264 VAAPI)**. Pass `/dev/dri` to the sidecar as described in [Enabling VAAPI](../video-streaming.md#enabling-vaapi-intel--amd-gpus). Record any hardware-specific N/A results separately from the local stack.
- [ ] Connect the TeamSpeak 6 desktop client to the server and open the web UI in a browser. Keep the browser Network tab open; note unexpected failed requests, especially HTTP 500 responses.
- [ ] Prepare two bots and, for isolation checks, two server configurations. Prepare these test sources:
  - one YouTube video;
  - one YouTube playlist with at least five videos;
  - one long YouTube video (over 15 minutes, ideally 30+);
  - one YouTube live broadcast;
  - one Twitch channel;
  - one Spotify track;
  - one Apple Music album or playlist link;
  - one radio stream;
  - one live IPTV channel from a LAN source allowed through **IPTV → Local hosts**;
  - one video file in the music folder, for the console's **Link** tab;
  - a valid PNG, JPEG or GIF avatar under 200 KB, an oversized image and a renamed non-image.

## 1. Shared volume and Now playing (#251, #264)

- [ ] Set a bot's volume while music plays, then start video and IPTV on the same bot. Both start at that level.
- [ ] `!vol 30` changes the volume for music, video and IPTV. The Bot Hub card and that bot's console show the same value.
- [ ] A music card shows the title, pause/resume, skip, volume and **Stop media**. The console progress bar and time advance.
- [ ] A video card shows the LIVE badge, preview, volume, **Stop stream**, and quality/encoder details.
- [ ] Idle/offline cards show the last stop reason. Start, stop, replacement and auto-stop update the card and console without a page reload.
- [ ] At 390 px wide, Bot Hub cards stack and the console uses one column without horizontal page scrolling.

## 2. Bot Hub, Media Library and old links (#265, #275, #285)

The old Bots, Queue, Video and Commands tabs were removed by #285. Check their replacement screens and redirects rather than expecting those tabs to remain.

- [ ] **Bot Hub** is the bot list: create, edit, start, stop and delete a test bot; check its server/channel and open its widget link dialog. Any failed action shows an error.
- [ ] **Open console** opens `/bot-hub/<id>` with the bot name and `Server · #channel`. The settings menu's **Edit bot** opens that bot's settings.
- [ ] **Media Library** has exactly **Library · Playlists · Radio stations · Requests · Streaming defaults**. Each tab loads; there is no bot selector for shared media.
- [ ] **Bot Flows** has **Flows · Chat commands**. IPTV playlist management and **Local hosts** remain on the IPTV page.
- [ ] Check every old link below. No redirect or deep link starts media by itself.

| Old link | Expected destination |
| --- | --- |
| `/media-bots?tab=bots` | Bot Hub |
| `/media-bots?tab=queue&bot=<id>` | That bot's console |
| `/media-bots?tab=queue` | Bot Hub |
| `/media-bots?tab=video&bot=<id>` | That bot's console |
| `/media-bots?tab=video` | Media Library → Streaming defaults |
| `/media-bots?tab=commands` | Bot Flows → Chat commands |
| `/media-bots?tab=radio&bot=<id>` | Media Library → Radio stations |
| `/media-bots?tab=requests` | Media Library → Requests |
| `/music-bots` and `/music-bots?tab=video&bot=<id>` | Same destinations as the corresponding `/media-bots` links |
| `/music-requests` | Media Library → Requests |

- [ ] With a stopped bot, the console says **Start the bot to play something.** and **Start bot** works. Stop the test TeamSpeak server and try again: the error appears under the button.
- [ ] `/bot-hub/999` shows **Bot not found** and **Back to Bot Hub**.

## 3. Queue and source tabs (#275, #278, #279)

- [ ] **Up next** contains only tracks after the playing one. Check the same queue from a second browser session after each action.
- [ ] Reorder with the mouse, with a phone press-and-hold on the handle, and with the keyboard (Tab to handle, Space, arrows, Space). The order survives reload and matches the second session.
- [ ] Queue the same song twice. **Play now** and **Remove** on the second copy act on that copy.
- [ ] Shuffle toggles; repeat cycles off/track/queue; clear empties Up next.
- [ ] Start radio with tracks queued: **Up next (n) is kept while the radio plays.** **Play queue** returns to those tracks. Radio says **Plays until stopped.**, with no progress or skip. **Stop**, **Stop radio** and **Stop stream** stop their respective media.
- [ ] Source tabs read **Music · Link · Radio · IPTV**. Each can start media; starting another type asks **Replace what is playing?** before replacing it.
- [ ] **Music → Songs** searches title/artist shortly after typing stops, without flashing **Loading songs…**. **Play** starts a song and **Queue** adds it without starting playback.
- [ ] With more than 50 songs, the pager shows `1–50 of N songs`. **Per page** offers 25/50/100 and remembers the choice after reload. Check paging on playlists, recent requests, radio and IPTV lists too.
- [ ] **Music → Playlists** shows the selected server's playlists and legacy shared playlists. **Play** replaces the queue; **Queue** appends.
- [ ] **Music → Recent requests** shows recent `!play` links; **Play** and **Queue** work.
- [ ] Open a server-B bot's console after a server-A bot's console: Songs and the other source lists belong to B. The console is scoped to its bot's server; changing the global header selection must not introduce another server's media into that bot's console. Check header-based server switching separately in Media Library.
- [ ] **Link** with a YouTube URL and **Play as music** starts music on **Play**.
- [ ] Choose **Stream as video**: video options appear and the button reads **Stream**. Change quality and check that the stream uses it.
- [ ] A music-folder filename disables **Play as music** with **Music-folder files play from the Music tab.** **Stream as video** streams the file. After replacing the filename with a URL, select **Play as music** manually if the choice stays on video.
- [ ] A Twitch channel URL streams as video. Both Link modes show the replacement prompt when another media type is playing.
- [ ] **Radio** search works. Mood chips show `All (n)` and each genre's count; selecting a chip filters the list. **Play** starts the station. The footer points to **Media Library → Radio stations** for editing moods.

## 4. Media URL pipeline and imports (#267, #268, #288)

Check each URL case in the console's **Link** tab and with `!play <link>` in channel chat. #288 split the handler; existing chat behavior should remain the same.

- [ ] A single YouTube URL plays at once.
- [ ] A YouTube playlist starts the first track and adds the rest in order, up to 25.
- [ ] Spotify and Apple Music resolve to YouTube and play. Apple Music tracks with no match are skipped without failing the rest.
- [ ] Enqueue-only actions never start playback.
- [ ] Stop while a playlist is loading: no tracks are added afterwards. Start a new playlist while another loads: only the new playlist fills the queue.
- [ ] Play a URL as music while video is active: the UI shows **Replace what is playing?**, rather than a resolver error.
- [ ] A bad YouTube URL gives a clear error, such as **Could not resolve that YouTube URL**; unrelated failures are not all reported as HTTP 502.
- [ ] In **Media Library → Library** or **Playlists**, import a YouTube playlist into a chosen bot's queue with **Clear queue first** ticked: the old queue is cleared. Unticked: imported tracks append to that bot's queue.
- [ ] Exercise existing chat commands after the handler split: playback, queue, pause/resume, skip, volume, playlist, radio, IPTV, stream/stopstream, help, custom replies and flow command triggers. Replies, permissions and flood handling behave as before.

## 5. Shared playlists and radio editing (#273, #266)

- [ ] `!playlist` lists all playlists on the selected server, including playlists created while another bot was selected. Both bots' consoles see the same songs, playlists, radio stations and IPTV channels.
- [ ] **Media Library → Playlists** filters by server. Legacy playlists with no server still appear on every server.
- [ ] Open a playlist and switch server in the header: the detail closes with **Select a playlist to view its songs**.
- [ ] Create a playlist on server B: it appears on B and not A.
- [ ] **Media Library → Radio stations → Edit** saves name, URL and **Mood or genre**, with **Station updated**.
- [ ] Rename a station with an already broken URL without changing its URL: the rename saves. Change its URL to a blocked/private address: an error appears and the station stays unchanged.
- [ ] Each radio Edit button names its station for keyboard/screen-reader users.

## 6. AMD VAAPI, NVENC availability and A/V sync (#238, #269)

- [ ] **Media Library → Streaming defaults → Check encoders** reports NVENC unavailable on this AMD host; supported VAAPI rows still pass.
- [ ] With hardware preferred, encoder **Auto** chooses **H.264 (VAAPI)**. A 1080p stream shows VAAPI without a software fallback warning.
- [ ] A 2160p stream runs at about 1.0x on VAAPI. Record speed, encoder and any warning.
- [ ] YouTube VOD at 24, 25 and 30 fps has matching picture and sound in the TS6 client.
- [ ] Live IPTV stays in sync after several minutes on AMD VAAPI. Have a viewer leave/rejoin mid-stream: picture returns within about one second and stays in sync.
- [ ] The browser preview still works.

NVENC encoding is **N/A on the AMD host**; the unavailable row is still a required check. #238's author reported RTX 5080 tests at 720p/2160p and viewer rejoin; that is prior evidence, not a homelab result. `docker-compose.nvidia.yml` applies only to NVIDIA hosts. #269 was tested by its author on Intel VAAPI/NVENC, making the AMD run necessary. Its defaults increase `SYNC_MAX_DELAY_MS` from 500 to 1000 and `VIDEO_QUEUE_SIZE` from 1024 to 4096; Compose already sets the queue to 8192. Record memory or sync regressions.

## 7. Direct YouTube streaming (#270)

Use **Settings → YouTube → Stream YouTube videos directly** (off by default).

- [ ] Switch off: a short video downloads/streams as before; a video over 15 minutes is refused with a message mentioning the switch.
- [ ] Twitch works with the switch both off and on.
- [ ] Switch on, AMD VAAPI, Auto quality: a 30+ minute video starts within seconds. A 1440p/2160p source has audio as well as video.
- [ ] A YouTube live broadcast plays with the switch on.
- [ ] A 24 fps clip stays in sync with #269 in place.
- [ ] Turning the switch off applies to the next stream without restarting.
- [ ] With the switch on, confirm the documented duration behavior for the UI and `!stream`: **Max video duration** does not limit direct YouTube streams. The no-viewer timeout still applies.

Known limits from #271: expiring YouTube URLs can end very long streams; volume changes restart a stream from the beginning; some networks receive HTTP 403, so downloading remains the default. #270's author tested NVENC only. Chat permission changes planned for 1.11 are outside this release.

## 8. Auto-stop notices (#274)

- [ ] Music and radio in an empty channel stop after the default five minutes and post one notice, for example **Stopped radio: the channel was empty for 5 minutes.**
- [ ] With a video no-viewer timeout longer than one minute, channel chat gets **Nobody is watching. The stream stops in 1 minute.**, then one stop notice.
- [ ] Join as a TS viewer after the warning: the stream stays active and no stop notice is posted. The browser preview alone does not count as a viewer.
- [ ] Turn off **Announce auto-stops in chat** in **Media Library → Streaming defaults**, press **Save defaults**, then start a new stream: both warnings and stop notices are suppressed. Running video/IPTV streams retain the setting captured when they started. Also check music/radio with the switch off. Restore and save the intended setting afterwards.
- [ ] A timeout of one minute or less produces the stop notice without a warning; the defaults text explains this. With the timeout off, no no-viewer countdown occurs.
- [ ] Check a server override and the global default separately. Notices do not duplicate, and a flood hold does not create a burst of delayed chat messages.

## 9. IPTV groups, favourites, recent and filters (#282, #286, #285, #293)

- [ ] **IPTV → Stream on…** opens the chosen bot's console with the right channel selected, including when channel names/keys repeat in a playlist. No stream starts until **Stream** is pressed.
- [ ] **Console → IPTV → Browse groups** lists groups/counts across playlists. Open a group, use **All groups**, and filter groups.
- [ ] **Search channels** searches across playlists; **Playlist → All playlists** and a single-playlist selection return the expected channels. Stream one with the chosen video options.
- [ ] Star/unstar a channel. **Favourites** is selected initially when favourites exist; otherwise **Browse groups** is selected. The stars are shared by bots on the same server and isolated between servers.
- [ ] A successfully started channel appears in **Recent**; a failed start does not. The list is capped at 20, newest first.
- [ ] Refresh/reorder a playlist: favourites and recent still resolve to the correct channel. Remove a saved channel from the playlist: its row says **No longer in this playlist**, cannot stream, and **Remove** clears the saved pick.
- [ ] A LAN playlist refreshes and streams only after its source host is allowed through **Local hosts**. Re-check [the Local hosts regression tests](164-1-9-0-rc-smoke.md#9-follow-up-fixes-197) without changing host firewall rules.

- [ ] Refresh a playlist whose channels carry `tvg-country` and `tvg-language` tags. **Console → IPTV** shows **Country** and **Language** filters; a playlist without those tags shows no filter.
- [ ] Pick a country, then a language: browse, search, Favourites and Recent all narrow to matching channels. A channel tagged with several countries or languages matches each of them. **All countries** / **All languages** clears the filter.
- [ ] Switch to a playlist that lacks the selected country or language: the filter resets instead of showing an empty list.
- [ ] A playlist that existed before the upgrade gets its filters after its first refresh; nothing is lost from favourites or recent.

## 10. Chat commands and clash warnings (#281)

- [ ] **Bot Flows → Chat commands** lists **Built-in commands** with their `!` names.
- [ ] Create/edit/enable/disable/delete a custom reply. Test it in chat and switch servers to check scope.
- [ ] Give a custom reply the same name as a built-in command or flow command trigger: **Command name clashes** appears. A command trigger in the flow editor shows **Command name clash** too.
- [ ] Change or remove the duplicate name: warnings update. Warnings do not prevent saving or silently alter command behavior.

## 11. Bot avatars (#261, #283)

#261's test script result was already recorded on 2026-10-02 in #259. Re-test the merged UI and reconnect behavior below.

- [ ] A newly created bot gets the default avatar in the TS6 client after connecting. The Bot Hub card and console header show it too.
- [ ] From the console's settings menu, choose **Edit bot**, then **Avatar → Upload** a valid PNG/JPEG/GIF at most 200 KB. It appears in the TS6 client and web UI. Reconnect the bot: the same custom image returns.
- [ ] Change an avatar while the bot is offline, then start it: the new image replaces the old remote file.
- [ ] **Use default** restores the default; **None** clears the TS avatar. Both choices persist after reconnect.
- [ ] An oversized image and a renamed non-image fail with a clear error, leaving the previous avatar intact.
- [ ] On an isolated test bot, remove its server-group file-upload permission (`i_ft_file_upload_power` below the server's requirement): the refusal, such as error 2568, is shown and the bot stays connected. Restore the permission and retry successfully.

## 12. Hosted channel banners (#287)

This merged after #271's last checklist update and also needs a real TS6 client check.

- [ ] In a channel's edit dialog, **Hosted banners → Upload** accepts PNG/JPEG/GIF/WebP within the displayed 5 MB limit. Oversized/invalid files show an error.
- [ ] Set **Public URL** to the manager's existing client-reachable address, select a hosted image, and save the channel. The TS6 client renders the banner. On a private host, use the existing private access path; the label does not require opening public inbound access.
- [ ] Change the public URL and verify the currently selected hosted banner updates. External banner URLs remain selectable.
- [ ] Cancel a delete, then confirm **Delete hosted banner** for a disposable image. The image disappears; channels still referring to it no longer display it. Audit History records upload/delete actions.

Docs-only PRs #258, #262 and #272 do not require media checks. #265's temporary tabs are covered by their final replacement screens in section 2.

## 13. Console polish, shortcuts and stream defaults (#290, #294, #295)

- [ ] The console header shows a **Connected** badge (**Offline** when the bot is stopped) next to the bot name. A screen reader announces connection changes.
- [ ] **Now playing** for music shows the time once, the queue position (for example **Track 2 of 8**), a labelled **Volume n%**, and a Pause / Skip / Stop row. Video shows a labelled facts grid. Idle and offline states are clear.
- [ ] **Up next** shows **Drag to reorder** and is hidden while radio or video plays with nothing queued. If the queue fails to load, an error shows instead of an empty list.
- [ ] **Link** shows **How should the bot play it?** with a one-line hint under each choice, and the button names what it will do.
- [ ] **Video options** is a folded row that shows the current choices. Quality starts on **Use bot default**; Encoder and **Stop with no viewers after** start on **Use server default** with the current value in brackets. Start a stream without opening the row: it uses the bot's preset and **Media Library → Streaming defaults** (or `VIDEO_ENCODER` / `VIDEO_NO_VIEWER_TIMEOUT_SECONDS` when nothing is saved).
- [ ] Pick an explicit value (for example **Auto** or a fixed quality) for one stream: only that stream changes. Picking the default option again goes back to inheriting. Change the server defaults and start another stream: it follows the new defaults.
- [ ] Click **Stream** straight after opening the console: the stream still uses the configured encoder, not a fallback.
- [ ] The edit and new bot dialogs are titled to match the menu (**Edit bot**, **New bot**). **Bot Flows → Chat commands** has no separate **Back to flows** button.
- [ ] Each **Play something** tab has a **+** shortcut: Songs → **Add songs**, Playlists → **Add playlist**, Recent requests → **Manage requests**, Link → **Add files**, Radio → **Add station**, IPTV → **Add playlist**. Each opens the right Media Library tab or the IPTV page and starts nothing.
