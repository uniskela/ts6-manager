# Development

See [PWA maintenance and validation](../internal/pwa-maintenance.md) for static cache boundaries, service-worker updates, deployment headers, and device QA.

Local development targets Node.js 20+ and pnpm 9.x. CI deliberately stays on pnpm 9 because newer pnpm majors change dependency build-script and override behavior.

## Setup

~~~bash
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install --frozen-lockfile
pnpm db:generate
pnpm dev
~~~

The backend runs on port 3001 and the Vite frontend runs on port 5173 by default.

## Useful workspace commands

| Command | Purpose |
|---|---|
| `pnpm dev` | Start workspace development servers |
| `pnpm dev:backend` | Start only the backend |
| `pnpm dev:frontend` | Start only the frontend |
| `pnpm build` | Build all packages |
| `pnpm typecheck` | Run workspace type checks |
| `pnpm audit` | Audit production dependencies |
| `pnpm db:generate` | Generate the Prisma client |
| `pnpm --filter @ts6/frontend docs:screenshots` | Rebuild the frontend and regenerate the fixture-based screenshots (dashboard, Bot Hub, media bots, IPTV, flows, permissions compare); does not update the Demo screenshots |

## Maintained screenshots

The documentation screenshots are generated by `packages/frontend/tests/docs-screenshots.spec.ts` against the production build and the opt-in fixture scenario in `serve-production.mjs`. The fixture uses generic demo identities, reserved `.test` URLs, and fixed browser time; it never reads local deployment credentials or personal infrastructure.

Run the screenshot command with pnpm 9 (fixture-based images only), review every changed image for readable text and shipped behavior, then run the normal production Playwright suite. The spec seeds the `ts6-ui` store with every sidebar section expanded; keep its `version` equal to `COMPACT_SIDEBAR_DEFAULTS_VERSION` in `ui.store.ts`, or the app's migration collapses System and Automation again. Do not substitute captures from a personal TeamSpeak deployment.

### Demo-server screenshots

`channels.png`, `clients.png`, `server-groups.png`, `permissions-editor.png`, `server-logs.png`, and `demo-connection.png` are **not** produced by `docs:screenshots`. Capture them from a running manager using the built-in Demo TeamSpeak Server; they contain only synthetic demo data.

1. Use pnpm 9, then `pnpm install --frozen-lockfile`, `pnpm db:generate`, and `pnpm --filter @ts6/common build`.
2. Start a scratch backend (`pnpm dev:backend` with a throwaway `DATABASE_URL`, `JWT_SECRET`, and `ENCRYPTION_KEY`; run `npx prisma db push` in `packages/backend` first) and the frontend (`pnpm dev:frontend`).
3. Open `/setup` to create a scratch admin, then add the demo connection (Settings → Connections → Add connection → Demo).
4. Set the UI to the Dark base theme with the Cyan accent, use a 1600×1000 viewport, and expand every sidebar section (System and Automation are collapsed by default), and capture the top-left 1600×960 region of each page: `/channels`, `/clients`, `/server-groups` (select Server Admin), `/permissions` (select Moderator and expand sections), `/logs`, and Settings → Connections.
5. Review each image for readable text before committing.

## Database

The backend uses Prisma with SQLite.

For local development:

~~~bash
cd packages/backend
npx prisma db push
npx prisma db seed
~~~

Docker production startup uses `docker-commands/apply-schema.sh` instead of requiring a manual migration step.

## Containers

**Full local stack with TeamSpeak 6 (beta13)** — preferred clone / PR happy path:

~~~bash
cp .env.pr-test.example .env
docker compose -f docker-compose.pr-test.yml up --build
~~~

Then open `http://localhost:3000/setup`, create the first admin, and log in. The bundled TeamSpeak connection (WebQuery + SSH Query) is seeded automatically when `LOCAL_DEV_BOOTSTRAP_CONNECTION=1`. Demo mode remains available separately.

**Manager only (no TeamSpeak container):**

~~~bash
docker compose -f docker-compose.local.yml up -d --build
~~~

Release images are published only from immutable releases, not ordinary pushes to `main`.
